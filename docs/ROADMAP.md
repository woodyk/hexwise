AI-assisted planning, October 31, 2026. These stages are proposed priorities, not delivery promises.

| Stage | Deliverable | Evidence required |
| --- | --- | --- |
| Current: Studio 0.2 | Inspectable bytes, provider adapters, snapshots/backups, prompt composition, HTML starters and explicit Git workflows | Local storage/HTTP/provider-shape tests, interactive workflows, retained limitations |

| 6. Training and representation studies | Curated requirements/bytes/change/evidence records | Provenance, project/build-separated splits, leakage controls and source/assembly baselines |
| 7. Systems and device experiments | Carefully scoped OS components, firmware and additional platforms | Disposable VM/device environments, boot and concurrency tests, explicit recovery |

## Immediate engineering priorities

- Diagnose native macOS Documents-folder access on the development machine.
- Improve target detection and validation without presenting header guesses as ABI certainty.
- Expand independent tests beyond the restricted ARM64 addition interpreter.
- Improve model proposal reliability, context selection and actionable failure reporting.
- Validate provider pagination, compatibility and model limits against live accounts where available.
- Add full project transactions, signature/package handling and distribution appropriate to each target.
- Keep architecture prompt coverage distinct from executable runner coverage.

## Measures of progress

Use independently verified changes per task, regression rate, attempts and total generation/evaluation cost. Compare prompted hex, assembly and source/compiler workflows under equivalent requirements. Track loadability separately from behavioral correctness, and record whether a model emitted a complete executable or used a packager.
